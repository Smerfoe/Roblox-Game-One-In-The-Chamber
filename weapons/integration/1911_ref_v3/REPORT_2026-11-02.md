## 3. How the new Tool is built

`ReplicatedStorage.Assets.Weapons.Service1911` was rebuilt from the import with the same names the scripts rely on:

- **Tool name:** still `Service1911`. Combat, inventory, loadout, skins and economy code are unchanged.
- **Joints:** `Handle` plus `SlideJoint`, `HammerJoint`, `TriggerJoint` and `MagazineJoint` (Motor6D), and `BarrelJoint` (Weld).
- **Attachments:**
  - `Grip`: its -Z axis points at the muzzle. Used by the viewmodel and by remote slide/hammer animation.
  - Pivots: `HammerPivot`, `TriggerPivot`, `MagazinePivot` and `SlidePivot`, placed on the manifest markers.
  - `Barrel.Muzzle`: on the manifest muzzle marker.
- **Grip placement:** matched to the old gun, measured from the trigger (0.329 studs behind and 0.123 below the trigger centre). The hand therefore lands in the same spot relative to the trigger as before.
- **Tool.Grip:** set to the same frame, so the third-person hold uses the same convention.
- **Part settings:** CanCollide, CanTouch, CanQuery, Massless and CastShadow were copied from the old parts. `ArtSource` and `ArtGLBSha256` attributes record the source.
- **Export:** the Tool is attached as `Service1911_Ref1911V3.rbxmx` (24 instances).

Grip-space comparison with the old gun: the muzzle is 1.087 studs forward and 0.360 up (old: 1.135 forward, 0.414 up). The new silhouette is slightly lower and shorter above the hand.

## 6. Remaining issues (for Codex and for approval)

1. **The model is mirrored (art).** The thumb safety, slide stop and magazine release are on the gun's **right** side and the ejection port is on the **left**.
   - From the shooter's view you see the ejection port side, and casings eject to the right, away from the port.
   - Cause: `build_reference_1911.py` puts the controls at `y = side*(-1)` and the port at `+y`. After the export rotation (muzzle → +Y), −Y becomes +X, which is the gun's right.
   - This was confirmed against the importer output (screenshots 02, 03, 04). It is not an importer problem.
   - Fix in Blender: swap the side for the controls and the ejection cutter, or mirror X and re-apply normals, then re-export.
   - Once fixed, re-import with the same steps; the Tool layout and attachments carry over.
2. **Sound cues still unassigned.** `Cloth` (equip and inspect), `RackPull`, `RackRelease` and `DryFire` have no entry in `PolishConfig.Sounds`.
   - Result: **the 1911 equip is now silent.** The old fallback "Rack" sound no longer plays when the timeline is active.
   - No IDs were invented. These need real recordings.
3. **Skins don't show on the new art.** SkinAppearance only changes `Color` and `Material`, and the SurfaceAppearance textures override both.
   - Slate, Desert and Crimson therefore look like the default.
   - Ownership, equipping and saving are unaffected.
   - Needs per-skin texture sets, or SurfaceAppearance `Color` tinting, in a later stage.
4. **Hands are blocky R15 hands with no fingers.** "Floating fingers" can't happen, but there is no finger wrap either. Real finger posing needs a fitted hand rig (also noted in Service1911Tracks).
5. **Unexplained knife sound.** During the two-client run, Player 1's camera played `Polish_Swing` twice with no click, while holding the Karambit after an auto-switch. Not investigated; it is outside the 1911 scope.
6. **Studio place not saved.** All changes above are live in the open Studio session only. Save the place yourself once you approve, or tell me to save it. Saving is not the same as publishing to live.
